# Gravity Perks evidence profile

This profile is qualification infrastructure for the exact Owner-supplied Gravity Perks 2.3.16 package. It does not claim generic Gravity Perks support and it does not ship a production adapter.

The profile creates an ephemeral real Perk plugin using the `Perk: True` header and the exact runtime `GWPerk` / `GP_Perk` mechanism. The fixture exists only inside the temporary WordPress lab and is never part of the Vazir production artifact.

It independently measures:

- the ordinary Gravity Perks wp-admin management page;
- exact 2.3.16 view-dispatch semantics from the installed licensed package;
- the legacy Documentation URL generated by `GP_Perk::get_link_for( 'documentation' )` and whether it actually reaches `GWPerksPage::load_documentation()`;
- the supported standalone Perk Settings document produced by `GWPerksPage::load_perk_settings()`;
- loaded stylesheet resources and WordPress style-pipeline sentinels;
- Google Fonts request attempts and any `fonts.gstatic.com` font requests on runtime-reachable surfaces;
- Vazirmatn requests inside each runtime-reachable document boundary;
- protected Dashicons / GFFontAwesome / FontAwesome families when actually rendered.

For exact Gravity Perks 2.3.16, the profile fails closed if the dispatcher semantics drift. If the installed source keeps the legacy `load_documentation()` implementation but does not dispatch any Perks `view` request to it, Documentation is recorded as `NOT_REACHABLE_AS_DOCUMENTATION`; source-only Google Fonts or typography observations from that dead path are not promoted to runtime claims. The generated Documentation URL is still exercised in Chromium to prove what the real dispatcher serves.

A typography mismatch on a supported/reachable surface is evidence (`FAIL` disposition for that surface), not a workflow failure. The workflow fails only when required qualification evidence cannot be produced truthfully. Missing or unreachable optional surfaces remain explicitly `NOT_PROVEN` / `NOT_REACHABLE` rather than being relabeled as successful runtime coverage.
